# 线程绑核基准说明

## 目标

`tests/bind_core_test.cpp` 用来比较 Linux 默认调度与手动绑核在两类负载下的差异：

1. **私有内存测试**：每个线程维护自己的工作集，观察线程迁移对私有缓存局部性的影响。
2. **共享内存测试**：所有线程共享一块大数组，并交错写入相邻元素，制造共享 cache line 压力，观察绑核与缓存一致性流量的影响。

## 构建与运行

在仓库根目录执行：

```bash
cmake -S . -B build
cmake --build build --target thread_affinity -j
./build/thread_affinity --threads 6 --buffer-size 8M
```

## 参数

程序支持以下参数：

- `--threads N`：线程数，默认等于在线 CPU 数。
- `--buffer-size SIZE`：每线程工作集大小，支持 `K/M/G` 后缀，如 `512K`、`8M`、`64M`。
- `--passes N`：每轮重复扫描次数，默认 `8`。
- `--warmup N`：预热轮数，默认 `2`。
- `--rounds N`：统计轮数，默认 `8`。
- `--help`：显示帮助。

说明：

- 私有内存测试中，`buffer-size` 表示**每个线程**独享的工作集大小。
- 共享内存测试中，总共享数组大小约为 `threads × buffer-size`，并采用交错写入方式提升 cache line 共享概率。

## 测试环境

- CPU：AMD Ryzen 5 4500U
- 核心 / 线程：6C / 6T
- 操作系统：Linux
- 构建：Release，`-O3`

### 汇总观察

| 现象                          | 观察                                                                                   |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 私有内存，小线程数            | `1` 线程和 `2` 线程在 `1M~8M` 上更容易看到正收益，说明私有缓存命中与线程稳定驻留有关。 |
| 私有内存，大工作集            | 到 `32M` 后结果分化明显，瓶颈逐渐转向 LLC 容量和内存带宽，绑核收益不再稳定。           |
| 共享内存，中等规模            | `2`/`4` 线程在 `1M~32M` 的共享写入测试里多为正收益，说明固定核心后调度抖动有所下降。   |
| 共享内存，高并发 + 超大工作集 | `6` 线程 `192M` 总共享数组几乎无收益，说明主要受内存系统限制，而不是调度迁移。         |
| 单线程                        | 单线程下仍有少量波动，更多反映测量噪声、DVFS 频率变化和系统后台负载，而不是绑核本身。  |

## 如何解读结果

1. **私有内存测试更适合观察迁核成本**
   - 每个线程有独立工作集。
   - 如果线程频繁迁移，私有缓存更容易失效。
   - 但当工作集远大于 LLC 时，瓶颈会转向内存带宽，绑核收益自然下降。

2. **共享内存测试更适合观察 cache coherence 和 false sharing 风险**
   - 各线程交错更新相邻元素，会共享 cache line。
   - 此时绑核不一定更快，因为主要成本可能来自写入一致性流量，而不是调度迁移本身。

3. **小幅差异要结合标准差看**
   - 如果均值差异接近标准差量级，通常不能认为收益稳定。
   - 建议在固定 CPU 频率、减少后台负载的条件下增加 `--rounds` 进一步确认。

## 建议的后续实验

- 提高 `--rounds`，用更多样本减少抖动。
- 增加 `--passes`，让单轮运行时间更长。
- 在共享内存测试里继续细分：
  - 只读共享
  - 分块写入
  - 明确制造 false sharing 的热点写入
- 结合 `perf stat` 观察 `cache-misses`、`LLC-load-misses`、`context-switches` 等指标。
